# 可视分析子系统 —— 使用与流程指南

> 在原「微博仿真可视化系统」基础上新增的**可视分析（Visual Analytics）**能力。
> 与原有「列表/图谱」式可视化不同，这里把**提问权交给分析师**：先把仿真数据
> 重构成有结构的维度空间，分析师按自己关心的舆情问题去**组合、筛选、下钻**。

---

## 一、解决的三个核心需求

| 需求 | 对应页面 | 能力 |
|---|---|---|
| ① 舆情事件生命周期，查看各阶段维度变化 | **舆情生命周期** `/lifecycle` | 自动分期（潜伏→爆发→扩散→衰退），任选维度看其在各阶段的构成演化 |
| ② 识别关键群体，条件组合筛选 | **关键群体识别** `/key-groups` | 按职业/社群/行为/影响力分层等任意维度切群体，支持多条件组合筛选，给出关键度排名 |
| ③ 识别关键用户（意见领袖/发起者/活跃者） | **关键用户识别** `/key-users` | ETL 预判角色，按角色+条件组合筛选排序，可下钻到个体行为轨迹 |

## 二、系统架构

```
原始仿真库 (user/post/follow/like/comment/trace/rec)
        │
        ▼  ETL 富化层  backend/etl/build_analysis_db.py
┌─────────────────────────────────────────────────────┐
│ va_event_fact   统一事实表（一行一个行为事件）          │
│ va_user_dim     用户维度（画像+社群+影响力分层+角色）    │
│ va_post_dim     内容维度（话题+情感+级联指标+阶段）      │
│ va_community_dim 社群维度（规模+主导话题/情感+极化）     │
│ va_meta         构建元信息 + 生命周期阶段边界           │
└─────────────────────────────────────────────────────┘
        │  （写回同一个 .db 文件，不破坏原表）
        ▼  可视分析 API  backend/api/va.py
  /va/status  /va/build  /va/catalog  /va/explore
  /va/lifecycle  /va/key-groups  /va/key-users  /va/user/{id}
        │
        ▼  前端三大视图  frontend/src/views/
  Lifecycle.vue   KeyGroups.vue   KeyUsers.vue
  （共用 components/VaStatusBar.vue 显示流程指引与构建状态）
```

**设计要点**
- 所有耗时计算（社群检测、情感打分、话题抽取、级联指标、生命周期分期、影响力分层、
  角色判定）在 ETL **一次性离线**完成并落库，API 层只做轻量聚合 —— 这是支撑 1 万用户
  规模的关键。
- `va_event_fact` 是「事实表」：把 post/repost/comment/like/follow 以及 trace 中的
  refresh/search/trend 等软行为统一成一张长表，去重且带完整维度，使通用聚合查询成为可能。
- `/va/explore` 是通用聚合端点：分析师选什么维度就 `GROUP BY` 什么，一个端点取代「一图一接口」。

## 三、启动方式

```powershell
# 1. 后端（指定要分析的仿真库）
cd visualization_system/backend
pip install -r requirements.txt          # 已含 networkx
$env:OASIS_DB_PATH = "C:\...\weibo_test\weibo_sim_qwen_huawei.db"
python main.py                            # 默认 8000 端口

# 2. 前端
cd visualization_system/frontend
npm install
npm run dev                               # 默认 5173 端口
```

> 也可在「系统概览」页用数据库切换器换库；换库后需在可视分析页**重新构建分析底座**。

## 四、一套具体的可视分析流程（6 步）

前端每个可视分析页顶部都有**流程指引条**，高亮当前所处步骤。

### 第 1 步 · 构建分析底座
进入「舆情生命周期」页 → 点击 **🚀 一键构建分析底座**。
系统对当前数据库跑 ETL，生成 `va_*` 表（百用户量级数秒，万用户量级数十秒）。

### 第 2 步 · 总览舆情生命周期
- 看 **生命周期主轴图**：事件量曲线 + 情感走势 + 四阶段背景带，把握舆情整体节奏。
- 切换 **拆解维度**（行为类型/情感/角色/影响力分层/话题/推荐驱动），
  在 **构成演化流图** 与 **各阶段构成对比图** 中观察该维度如何随阶段变化。

### 第 3 步 · 锁定关键阶段
在四阶段卡片中点击你判断为「关键」的阶段（通常是**爆发期**或**扩散期**）将其**锁定**。
锁定后，群体/用户分析会自动聚焦该阶段。

### 第 4 步 · 识别关键群体
进入「关键群体识别」页：
- 选 **群体划分维度**（如 职业、社群、行为标签、影响力分层）。
- 用 **条件组合** 叠加筛选（如「职业=媒体」且「行为标签=内容生产者」）。
- 看 **群体识别图**（活跃度×影响力×规模散点）与 **关键度排名**，定位主导舆情的群体。
- 点击某群体 → 携带该群体条件跳转到关键用户识别。

### 第 5 步 · 识别关键用户
在「关键用户识别」页：
- 选 **角色**（意见领袖/讨论发起者/活跃用户/…）+ **排序依据**（影响力/PageRank/被转发/活跃度…）。
- 继续叠加 **条件组合**，在选定群体内进一步收敛。
- 看 **角色构成** 与 **关键用户排名**，确定核心人物。

### 第 6 步 · 个体溯源
点击用户表任一行 → 弹出**个体溯源**面板：画像、行为构成、各阶段活跃度、
逐小时行为轨迹、发布内容（含情感/级联指标），完成从宏观到个体的闭环。

> 通用探索入口：`/va/explore` 已就绪，后续可加一个「自由分析工作台」页面，
> 让分析师拖拽任意维度到行/列/颜色自由出图。

## 五、数据模型说明

### 维度（可切片）
- **用户维度**：社群、影响力分层（头部/腰部/长尾）、行为标签（内容生产者/活跃互动者/
  潜水观望/沉默用户/普通参与者）、关键角色、性别、地区、职业、账号类型、内容偏好。
- **内容维度**：话题、情感极性（正面/中性/负面）、立场（预留）。
- **行为维度**：行为类型、是否推荐驱动。
- **时间维度**：舆情阶段、小时。

### 度量（可聚合）
行为数、独立用户数、涉及内容数、平均情感分、正/负面占比、推荐驱动占比。

### 关键角色判定规则（ETL 内）
| 角色 | 判定 |
|---|---|
| 意见领袖 | 影响力分层=头部 且 被转发/获赞 > 0 |
| 讨论发起者 | 发过 级联规模≥3 的原创帖 |
| 活跃用户 | 行为事件数处于全体前 15% |
| 普通传播者 | 有过转发行为 |
| 边缘用户 | 其余 |

### 影响力分数
`log(粉丝) ·3 + log(被转发) ·2.5 + log(获赞) ·1.5 + log(原创数) ·2 + PageRank ·50`，
再按分位数切 头部(前10%)/腰部(10–40%)/长尾。

## 六、后续扩展点（已预留接口）

1. **立场信息**：`va_post_dim.stance` 字段已预留，`post.stance` 维度已在目录中。
   后续标注完成后，在 ETL 里写入该字段即可，前端各页的「拆解维度/筛选条件」自动可用。
2. **决策中间变量**：在 `va_event_fact` 或 `va_user_dim` 增加数值列，并在
   `backend/api/va.py` 的 `DIMENSIONS` / `MEASURES` 字典登记，前端无需改动即可选用。
3. **情感打分**：当前为 `etl/lexicon.py` 词典法（无第三方依赖）。如需更准，
   可替换为模型打分，写回 `sentiment_score / sentiment_class` 同名字段即可。
4. **用户画像**：ETL 会尽力从 `top100_users_complete_data_*.json` 按用户名匹配
   性别/地区/职业等。万用户场景下请保证画像文件与仿真库同目录、用户名可对齐。
