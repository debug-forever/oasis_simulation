# 舆情可视化 + 关键人物/群体识别 — 详细说明

> 配套前端：`index.html`（http://localhost:8765/）
> 数据来源：`weibo_sim_qwen_huawei.db`（100 用户、~1100 条 post/comment、24 小时仿真）

---

## 总览

### 需求映射

| 原始需求 | 对应图 |
|---|---|
| 可视化舆情，包含新闻学指标 | A1 / A2 / A3 / A4 / A5（5 张） |
| 识别舆情事件的关键人物 / 关键群体 | B1 / B2 / B3（3 张） |
| 没有显式群体概念，从用户属性 + 关系网络推导群体 | B1 提供 6 种群体定义并列对比 |
| 视觉分析"特征暴露"流程 | B2 PCP（多维同视图），Tukey/Inselberg 范式 |

### 整体设计

- **A 组（舆情）**：把 5 个传播学经典理论各对应一张可视化，从"事件演化"到"情感分布"到"叙事框架"到"极化"到"沉默"五层递进。
- **B 组（关键人物/群体）**：从"群体画像"（B1）→"个体多维筛选"（B2）→"群体随时间迁移"（B3）三步走。
- **统一视觉时间轴**：A1 自动识别的 4 个阶段（潜伏 / 爆发 / 持续 / 衰退）会作为底色出现在 A2 上，让"舆情"和"情感"对齐到同一时间线。
- **统一群体定义**：A3 / A4 用的"社区"都是 follow 图上 Louvain 切的同一份社区，不会出现一会用 KMeans 一会用 hierarchical 的混乱。

### 数据

- 表：`user / post / comment / like / follow / trace / rec`
- 注解流水线：`build_data.py` 一次扫库 → 在内存里给每条 post / comment 打上 `(sent_label, frame, stance, ...)` → 13 个 builder 各自聚合写出 `data/*.json`。
- 每张图都不直接读 DB，都读静态 JSON。10K 数据下也是离线一次跑、前端纯渲染。

## A · 舆情视图

### A1 — 议题生命周期

**理论 / 论文**
- Anthony Downs (1972). *Up and Down with Ecology – the Issue-Attention Cycle*. The Public Interest.
- 经典 5 阶段模型在新闻传播研究里被简化为 4 阶段："潜伏 → 爆发 → 持续 → 衰退"。

**数据来源**
- `post.created_at`、`comment.created_at`、`like.created_at`
- 注意：**`follow` 故意排除**，否则注册时刻的 sign-up 浪潮会人为把"潜伏期"拉到 0。

**算法**
1. 1 小时为 bin 聚合 post/comment/like 事件量。
2. 找全局峰值 `peak_idx`。
3. 阶段反推（基于"距峰值的相对量"）：
   - 潜伏期 = 起点 → 第一次 ≥ 20% 峰值
   - 爆发期 = 上一步终点 → 峰值
   - 持续期 = 峰值 → 衰退期起点之前
   - 衰退期 = 峰值之后第一次 < 50% 峰值 → 终点
4. 阶段以 `markArea` 半透明背景画在堆叠面积图上，主图叠 post/comment/like 三类堆叠 + 总声量虚线。

**视觉编码**
- x = 时间（每小时）
- y = 事件数（堆叠）
- 颜色：post 蓝、comment 橙、like 绿、总声量白虚线
- 背景色块 = 阶段（潜伏蓝 / 爆发橙 / 持续绿 / 衰退灰）

**怎么读**
- 峰值出现在哪个 bin → 议题"进入舆论中心"的时点。
- 衰退期 / 总长 比例 → 公众注意力疲劳速度。比例越大说明事件"易消逝"。
- 持续期长度 → 议题"上桌"持续多久；持续期短而衰退期长 → 注意力快速消散。

**当前数据集发现**
- 峰值出现在 03-26 07:00（仿真开始约 24 小时后）。
- 4 阶段大致占比：潜伏 53% / 爆发 4% / 持续 13% / 衰退 30%。
- 总声量 ~1700 个事件，符合 Downs 经典曲线（"长潜伏 + 短爆发"）。

**已知局限**
- 阈值 20% / 50% 是经验值，对短事件（< 12 bin）不稳定。
- 当前不区分议题（all-in-one），下一版可加"议题切片"使每个关键词都有自己的生命周期。

### A2 — 情感时序流

**理论 / 论文**
- Bo Pang & Lillian Lee (2008). *Opinion Mining and Sentiment Analysis*. Foundations and Trends in Information Retrieval.

**数据来源**
- `post.content + post.quote_content`、`comment.content`
- 经预处理后每条得到 `sent_label ∈ {-1, 0, +1}`

**算法（纯规则 + 词典法）**
1. 词典：
   - `POS_WORDS`（约 60 个）：好/棒/赞/支持/真香/碾压/逆袭/...
   - `NEG_WORDS`（约 50 个）：差/烂/翻车/智商税/抵制/挤牙膏/...
2. 否定回退窗口：每个命中前向看 3 字符内有无 `不/没/非/无/别/勿/未`，命中则翻转极性。
3. `sent_label` = sign(pos − neg)；pos == neg → 0。
4. 按小时 bin 聚合，分 +1 / 0 / −1 三条堆叠面积线。
5. 复用 A1 的阶段背景色块。

**视觉编码**
- x = 时间，y = 事件数
- 绿（正）/ 灰（中）/ 红（负），堆叠面积
- 阶段背景同 A1

**怎么读**
- 负面突然抬升 + 处于"持续期" → 风险转折信号。
- 持续期主导色 = 绿 → 顺民意发酵。
- 衰退期出现负面尖峰 → "翻车收尾"型事件。
- 中立量大且稳定 → 大多数声量是事实型/转述型，缺乏强观点。

**当前数据集发现**
- 全周期总分布：正 522 / 中 571 / 负 5 — 几乎一边倒正面。
- 爆发期同时出现正面和中立的双峰，没有明显负面尖峰。
- 这是仿真 LLM（Qwen-Huawei prompt）天然偏置的结果，**不是 demo 的算法问题**。

**10K+ 数据下扩展**
- 词典扫描 O(N · |dict|)，10w 帖子 < 1 分钟，结果可缓存到 `post.sent_label` 列。
- 升级路径：替换为 `uer/roberta-finetuned-jd-binary-chinese` 等中文情感模型，单条 < 1ms。

**已知局限**
- 反讽/隐喻不识别（"真香"是正面词，但讽刺语境下意思反过来）。
- 不识别多议题混合句，"鸿蒙好但价格贵"会拆成 +1 + −1，最后中性。

### A3 — 框架光谱

**理论 / 论文**
- Robert Entman (1993). *Framing: Toward Clarification of a Fractured Paradigm*. Journal of Communication, 43(4).
- Framing = 选择某些事实方面，使之在交流文本中更突出，从而推动一种特定的问题定义、因果解释、道德评价或处理建议。

**数据来源**
- 同 A2。每条文本被打上"主导框架"。

**算法（关键词命中 + argmax）**
1. 5 个框架的关键词集（消费科技领域硬编码）：
   - **民族叙事**：国货 / 国产 / 中国 / 民族 / 自主 / 自研 / 崛起 / 制裁 / 卡脖子 ...
   - **技术创新**：鸿蒙 / HarmonyOS / 芯片 / 麒麟 / 5G / 影像 / 续航 / 工艺 / 算法 ...
   - **产品质量**：做工 / 质量 / 流畅 / 卡顿 / 发热 / 故障 / 丝滑 ...
   - **价格价值**：价格 / 便宜 / 贵 / 溢价 / 性价比 / 优惠 / 万元 ...
   - **生态体验**：生态 / 应用 / 互联 / 同步 / iCloud / 跨端 / 车机 ...
2. 每条文本对每个框架的关键词数累加，取最大值的那个框架为"主导"。
3. **平局靠字典定义顺序破** —— 当前实现下 ties 偏向"民族叙事"和"技术创新"。
4. 上图：按时间 bin 堆叠 5 个框架占比。
5. 下图：把每个 Louvain 社区当一行，每个框架当一列，做 frame × community 热力矩阵。

**视觉编码**
- 上图 x = 时间，y = 命中数堆叠；下图 x = 框架名，y = 社区编号，色深 = 命中数。

**怎么读**
- 上图：主导色块如果在阶段切换时也切换 → 框架替换；如果一直一种色 → 单一叙事垄断。
- 下图：如果两个社区在同一框架上都偏深 → 共识；如果在不同框架上偏深 → "框架割裂"，是潜在极化信号。

**当前数据集发现**
- 主导框架长期是"技术创新"，"民族叙事"和"生态体验"次之。
- 没有"价格价值"主导的窗口 — 表明此次仿真讨论以技术为主而非价格战。

**已知局限**
- 每条文本只取一个主导框架，但实际语境常多框架并存。
- "中国" / "美国" 等政治地理词只命中"民族叙事"，但有时它们是产品市场词（如"中国售价"）→ 可能误归类。
- 升级路径：multi-label 加权（每条对每个框架贡献 [0,1] 分数），让 stack 更平滑也更如实。

### A4 — 群体极化雷达

**理论 / 论文**
- M. Conover et al. (2011). *Political Polarization on Twitter*. ICWSM.
- J. Esteban & D. Ray (1994). *On the Measurement of Polarization*. Econometrica.
- Esteban-Ray 极化指数：
  P_ER = Σᵢ Σⱼ pᵢ^(1+α) · pⱼ · |yᵢ − yⱼ|
  - pᵢ = 第 i 个群体的人口占比
  - yᵢ = 第 i 个群体的"立场均值"
  - α = 1.6 (同质偏好，标准 ER 范围 0–1.6)

**数据来源**
- Louvain 在 follow 无向图上的社区划分（NetworkX 3.3 内置实现，random_state=42）。
- 立场：每条 post 经 `stance_score()` 打 `pro_hw / pro_ap / neutral / none`，用户立场 = 其 post 立场均值映射到 {1, -1, 0}。
- 框架：用户的所有 post 框架命中累加 → 5 个 frame 占比向量。
- 情感：用户的所有 post 情感均值。

**算法**
1. 仅保留 ≥ 3 人的社区。
2. 每个社区计算 9 维雷达：
   - 倾向华为占比（成员立场均值 > 0.1 的比例）
   - 倾向苹果占比
   - 情感正向占比
   - 情感负向占比
   - 5 个 framework 占比
3. 计算 P_ER（α=1.6）和社区间立场加权方差。
4. ECharts radar，每个社区一条线、半透明面。

**视觉编码**
- 9 个轴均归一到 [0, 1]
- 每个社区一条彩色雷达线
- 顶部数字 = ER 指数 + 立场方差（"舆论场分裂程度"两个量）

**怎么读**
- 雷达形状对立的两个社区（一个偏上一个偏下） → 极化对。
- ER 指数 > 0.1 视为"明显极化"；本数据 ER ≈ 0.011 → 几乎无极化。
- 立场方差衡量"社区间立场漂移程度"，与 ER 互补（ER 加权了群体规模）。

**当前数据集发现**
- 社区数 ~6 个 (≥ 3 人)，所有社区立场均值都偏正（亲华为）。
- ER 指数 0.011，方差 ≈ 0.04 — 完全没有极化。这本身是个发现：当前仿真没产出对立阵营。

**10K+ 数据下扩展**
- Louvain 在 10w 边以下分钟级；所有指标聚合到社区粒度，与用户数解耦。
- 可加 KOL bridge 边界：跨社区影响力高的 KOL 作为"极化对立面之间的桥"。

**已知局限**
- 立场只判断华为 / 苹果二极，未来多议题（华为 vs 三星 vs 苹果 ...）需要扩展为 multi-stance。
- Louvain 对 random seed 略敏感 — 同一份图重跑可能切出略不同的社区。

### A5 — 沉默的螺旋

**理论 / 论文**
- Elisabeth Noelle-Neumann (1974). *The Spiral of Silence: A Theory of Public Opinion*. Journal of Communication, 24(2).
- 核心：少数派感知到自己是少数后，发声意愿下降，进一步显得稀少 → 螺旋下沉。

**数据来源**
- 每个用户的所有 post + comment 立场分布 → 多数票决定该用户的"立场归属"（majority / minority / 未表态）。
- 全局多数立场 = 总声量更大的那个（数据中是 pro_hw）。

**算法**
1. 总声量决定多数派立场（`pro_hw`）/ 少数派立场（`pro_ap`）。
2. 每用户聚合自己 post+comment 立场分布，多数即归属。
3. 按小时 bin 分别绘制"多数派用户的发声量"和"少数派用户的发声量"。
4. 沉默指数 = 1 − 当前少数发声率 / 基线（基线 = 前 4 个 bin 的少数均值或前 25%）。

**视觉编码**
- 左 y 轴：声量（双曲线 + 半透明面积）
- 右 y 轴：沉默指数 [0, 1]，黄色虚线
- x = 时间

**怎么读**
- 多数升 + 少数下行 + 沉默指数升高 → 经典螺旋。
- 少数中后期反弹 → 反沉默事件（如关键论据出现）。
- 沉默指数顶部接近 1 → 少数已彻底沉默。

**当前数据集发现**
- 少数派（亲苹果）只有 1 个用户。"沉默"从仿真开局就是事实，不是动态过程。
- 这是数据本身的偏置（LLM 仿真没产出对立阵营），可视化忠实呈现。

**已知局限**
- 沉默基线敏感于 N 较小时的边界效应（前 4 bin 内若少数派活跃 → 后期下降会被高估）。
- 不能区分"主动沉默"（被群体压制）和"被动沉默"（个体不再上线）—— 后者可结合 trace 表里的"上线 gap"进一步推断。

## B · 关键人物 / 关键群体识别

### B1 — 群体雷达图谱（6 种群体定义并列）

**理论 / 论文**
- Tamara Munzner. *Visualization Analysis & Design* (Ch.12 — Multiform & Coordinated Views, Small Multiples).
- Jacques Bertin. *Sémiologie graphique* (1967) — small multiples 经典出处。

**为什么要 6 种？**
当前仿真没有显式人口学标签（年龄 / 城市 / 性别），所以"群体"必须从信号推导。一种切群方式可能漏掉重要结构，因此并列展示 6 种切法，让分析者比较"哪种切法暴露出最有判别力的群体差异"。

**6 种群体定义**

| 编号 | 定义 | 推导方式 |
|---|---|---|
| G1 | 网络社区 | follow 图 Louvain |
| G2 | 行为画像簇 | trace 表动作分布 KMeans (k = min(5, N/5)) |
| G3 | bio 角色 | bio 文本规则（官媒/科技博主/商家/生活/普通） |
| G4 | 影响力分层 | 粉丝数 quantile 50 / 90 → 长尾 / 腰部 / 头部 KOL |
| G5 | 立场簇 | 用户 post 立场均值阈值（亲华为 / 亲苹果 / 中立 / 未表态） |
| G6 | 时段画像 | trace 表小时分布 modal（上午/下午/晚上/深夜） |

**8 维特征（每个雷达的轴）**
1. 声量（post + comment 数）
2. 获赞转发（post 收到的 likes + shares）
3. 粉丝数
4. 跨群度（邻居在异社区比例）
5. 情感倾向（自身发文情感均值）
6. 原创率（原创帖数 / 总帖数）
7. 响应速度（trace 平均间隔的倒数）
8. 传播深度（自己原创帖被回复的最大深度）

**算法**
1. 上面 8 维都按"用户内值"算一份（per-user feature vector）。
2. 每种群体定义内部，组成员的 8 维取平均得到组的雷达向量。
3. **每种群体定义独立归一化**到 [0,1]（max-min within scheme），保证雷达可读。
4. 6 个群体定义各画一张雷达 small-multiple；同一定义内的多个子群叠加显示。

**怎么读**
- 选择"哪种群体定义最能拉开雷达形状差异" → 找到对该议题最有解释力的切群方式。
- 形状最异常的子群 = 关键群体候选。
- 跨群体定义比对：如果 G3 头部和 G4 头部是同一群人，说明"科技博主"和"高粉用户"高度重合。

**当前数据集发现**
- G3（bio 角色）切出 5 个子群但雷达高度同形 → bio 文本判别力弱（仿真 bio 都很泛）。
- G4（影响力）切得最干脆：头部 KOL 在"声量""获赞"两个轴远高于其他。
- G5（立场）只有 1 个亲苹果用户，无法成"群"。

**10K+ 数据下扩展**
- 群体数本身有限（每种切法一般 < 30 子群），雷达数量恒定。
- 8 维全是聚合特征，O(N) 一次扫描即可。

**已知局限**
- 用户没自带人口学标签，6 种切法都是"信号推导"。如未来有真实标签（地域 / 年龄），G7-G9 可直接加。
- 8 维归一化用的是 max-min，对单点 outlier 敏感（一个 50w 粉用户会把"粉丝数"轴压扁）。

### B2 — 关键人物多维仪表（平行坐标）

**理论 / 论文**
- Alfred Inselberg (1985). *The Plane with Parallel Coordinates*. The Visual Computer, 1(2).
- 平行坐标是高维空间在 2D 屏幕上"全保真"展开的少数手段之一；也是视觉分析"特征暴露"流程的标准工具。

**数据来源**
- 每个用户的 10 维特征向量（A4 计算的同一份），但 PCP 上仅显示 6 维以避免轴间挤压。
- 颜色按 bio 角色分（B1 G3 的同一份分类）。

**6 维（精选）**

| 维度 | 物理含义 |
|---|---|
| 发帖 | post 总数 |
| 粉丝 | num_followers |
| 获赞 | post 收到的 like 总数 |
| 跨群度 | 用户邻居中跨社区比例 |
| 情感 | 自身 post 情感均值 |
| 中介度 | networkx betweenness_centrality（在 follow 无向图上） |

**为什么减到 6 维？**
- 原计划 10 维（含评论 / 原创 / 被转 / 原创率）但屏幕宽度下轴名挤压。
- 6 维同时覆盖"声量 / 影响范围 / 关系结构 / 情感 / 中心性"，足够暴露关键人物。

**算法**
1. 全用户 6 维特征 min-max 归一化到 [0,1]。
2. 每条折线代表一个用户。
3. 折线颜色 = bio 角色。
4. 鼠标悬停显示原始数值（未归一化）。
5. 支持点击坐标轴拖出 brushing 区间过滤。

**怎么读 — 特征暴露的标准动作**
1. 找在多个轴都偏高的折线 → 多维联合极值用户（"全才型 KOL"）。
2. 找形状一致的折线带 → 同类用户簇（颜色聚类 ≈ 自然簇即说明 bio 角色与多维特征对齐）。
3. 找异常折线（其它都低唯一某维高）→ "单点突出"用户，可能是新晋 KOL 或刷量账号。

**当前数据集发现**
- 几个用户在"中介度 + 跨群度 + 粉丝"都偏高 → 典型 broker 型节点（结构洞）。
- 颜色按 bio 角色聚类不明显 — bio 文本和实际行为几乎无关，再次印证 G3 切群弱。

**10K+ 数据下扩展**
- 10K 折线全画会糊。建议：
  1. 默认仅展示 KOL（粉丝前 1%）+ 抽样 5%。
  2. brushing 后以"过滤命中用户"为目标动态加载更多折线。
- ECharts parallel 在 Canvas 渲染下 1K 条流畅，3K 条勉强，> 5K 必须降采样。

**已知局限**
- 6 维难以同时观察；多步 brushing 才能锁定目标。
- ECharts 自带的 brushing 不能跨多个 axis 组合 — 只能一次过滤一个轴。

### B3 — 群体演化流（立场 Sankey）

**理论 / 论文**
- Liu, S. et al. (2013). *StoryFlow: Tracking the Evolution of Stories*. IEEE TVCG, 19(12).
- Alluvial / Sankey 图最早见于 Sankey (1898)，在故事/群体演化场景下被 StoryFlow 系统化。

**为什么用 Sankey 而非 streamgraph？**
- 时间窗口分桶 + 离散类别 = 标准的 alluvial 任务。
- 比 streamgraph 更清楚地展示个体迁移路径（"从亲华为变到中立"是单条带状链路）。

**数据来源**
- post + comment 时间戳 + 立场标签
- 把整个仿真时长均分 5 个等长窗口

**5 个立场类别**
- 亲华为
- 亲苹果
- 中立
- 未表态（在该窗口内有发言但 stance = none）
- 离场（在该窗口内没有任何 post / comment）

**算法**
1. 时间窗口边界 = 总时长 / 5。
2. 每用户在每窗口内：统计 stance 多数票决定其类别；若该窗无发言则 = 离场。
3. 相邻窗口间累计同类→同类人次 → Sankey 链路 value。
4. 节点 = 25 个（5 cat × 5 窗口）。
5. 标签智能抑制：只有节点流量 ≥ max × 5% 才显示标签，避免小节点堆叠。
6. 颜色映射：亲华为红 / 亲苹果蓝 / 中立灰 / 未表态深灰 / 离场最深。

**怎么读**
- 大量"亲华为 → 离场" → 公众参与衰减（仿真中往往是事件结束）。
- 大量"中立 → 立场" → 极化新生（有人开始下场表态）。
- "立场 → 反向立场"链路 → 摇摆用户，是劝说叙事最有效的对象。
- 中立列粗细稳定 → 沉默大多数稳态。

**当前数据集发现**
- 主导链路：离场 → 离场（仿真前期没人发言）→ 后期突然涌入"亲华为"。
- 没有亲华为 ↔ 亲苹果 互转的链路 — 立场改变是"中立 ↔ 立场"而非"立场 ↔ 反向立场"。

**10K+ 数据下扩展**
- 节点数固定为 cats × windows（< 50），与用户数无关。
- 链路数 ≤ cats² × (windows-1) = 100，渲染零压力。
- 升级到滑动窗口（重叠 50%）能更平滑地展示连续迁移。

**已知局限**
- 5 等长窗口对"前空后挤"型事件不友好；可以改为"按累计声量等分"做事件感知的窗口切分。
- 类别只有 5 种，多议题场景下需要扩展（如"亲华为-技术框架" vs "亲华为-民族框架"）。

## 当前数据集偏置说明（重要）

我们用的仿真数据集本身有几个偏置，可视化是忠实呈现，不是 bug：

1. **正面占比 99%+**：LLM 仿真 Qwen-Huawei prompt 让所有用户偏好正向表达，A2 几乎一边倒绿。
2. **亲苹果只有 1 人**：极化和沉默螺旋"无对立阵营"是这个事实的结果。
3. **议程一致性极高**（媒体 vs 公众 Spearman ρ ≈ 0.97 — 这个图已删，但数据保留）：意味着仿真没产出"小众议题"。
4. **关注网络是 sign-up rush 期产生的**：所以 A1 排除了 follow 事件。

如果接入真实微博数据，以上现象会自然消失，可视化的判别力会立刻显现。
